How it works

Five small pieces, no server

Capture

A private Telegram bot accepts any text I send. It replies instantly, so I know the note is safe before I pocket the phone.

Relay

Telegram's webhook calls a Google Apps Script web app. It timestamps the text and writes it as a Markdown file through the GitHub API.

Store

Every capture is a commit in a private repo, so nothing is lost and every change has history.

Sync

The Obsidian vault on my PC is the same repo. A git pull brings the raw notes into 01_INBOX.

Process

On "check my bot inbox", Claude reads the new captures under the vault's written rules, links each one to its related notes, and offers the next study step.

Guardrails

Automation that refuses to make things up

A fast capture is useless if the machine embroiders it. These rules live in the vault's instruction file, and the processing follows them every time.

No invented factsA one-line capture stays one line. It is linked to the right notes, never expanded into a "complete" note it doesn't support.
Junk stays putGreetings, /start, and truncated or duplicate captures are skipped and left in the inbox, not turned into notes.
Delete only after it's safeA raw file is removed only once it is faithfully represented somewhere else.
Marked as unverifiedCaptures sit in their own UNVERIFIED file and are never turned into flashcards.
No identifiersStudy notes only. Anything that could identify a person is scrubbed.
